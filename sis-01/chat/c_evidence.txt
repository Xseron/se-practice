(Evidence 1) Sommerville, Software Engineering, 10th ed., Global Edition, ch. 1, section 1.1.2, p. 26: the fundamentals that apply to all types of software are (1) a managed and understood development process, planned so that it is clear what will be produced and when, with the specific process depending on the type of software; (2) dependability and performance: behave as expected without failures, be available when required, be safe and secure, and not waste resources; (3) understanding and managing the specification and requirements, including managing users' expectations so a useful system is delivered within budget and schedule; (4) effective use of existing resources: where appropriate, reuse software that has already been developed rather than write new software. The same page says that for an interactive web-based system, iterative development and delivery is the best approach. (Evidence 2) PostgreSQL 18 documentation, section 8.17.10 "Constraints on Ranges", https://www.postgresql.org/docs/current/rangetypes.html (accessed 2026-10-11): an exclusion constraint prevents overlapping ranges from existing in the table at the same time; with the btree_gist extension installed, EXCLUDE USING GIST (room WITH =, during WITH &&) rejects overlapping ranges only when the room is the same, and the overlapping insert fails with an error. Section 8.17.6 says a range built from two values includes the lower bound and excludes the upper bound by default, so a booking that starts exactly when another ends does not conflict.
