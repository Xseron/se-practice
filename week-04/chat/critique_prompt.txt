## Scenario (from the Lesson 04 practice deck, slide 7)

Students view room availability, book a room, and cancel their own bookings. Administrators block
or unblock rooms and review usage.

- **R1** Future start, with duration greater than 0 and at most 2 hours.
- **R2** Active bookings for the same room cannot overlap.
- **R3** A blocked room cannot accept a new booking.
- **R4** A successful booking produces a confirmation.

## Reference set

| ID | Story | Rules |
| --- | --- | --- |
| US-01 | As a student, I want to book a free study room for a time slot, so that I have a place to work, and I get a confirmation when the booking succeeds. | R1, R2, R3, R4 |
| US-02 | As a student, I want to see which rooms are free at a given time, so that I can choose one before booking. | — |
| US-03 | As a student, I want to cancel one of my own bookings, so that the room is released for others. | R2 |
| US-04 | As an administrator, I want to block a room, so that no new bookings can be made for it. | R3 |
| US-05 | As an administrator, I want to unblock a room, so that students can book it again. | R3 |
| US-06 | As an administrator, I want to review how rooms are used, so that I can plan capacity. | — |

**Out of scope** (do not model): payments, equipment in rooms, recurring bookings, waiting lists,
notifications other than the booking confirmation, user registration.

models/sequence.puml:
```plantuml
@startuml sequence
title Book room (US-01) - rules R1, R3, R2, then R4 (revised)

skinparam shadowing false
autonumber

actor Student
participant "BookingService" as BS <<service>>
participant "BookingRepository" as BR <<repository>>

Student -> BS : bookRoom(studentId, roomId, start, duration)
activate BS

BS -> BS : validateTimeSlot(start, duration)
note right
  R1: start > now
  and 0 < duration <= 2 h
end note

alt R1 violated
  BS --> Student : rejected(INVALID_TIME_SLOT)
else time slot valid
  BS -> BR : isRoomBlocked(roomId)
  activate BR
  BR --> BS : blocked : Boolean
  deactivate BR

  alt room blocked (R3)
    BS --> Student : rejected(ROOM_BLOCKED)
  else room not blocked
    BS -> BR : findActiveOverlapping(roomId, start, start + duration)
    activate BR
    BR --> BS : overlapping : Booking[*]
    deactivate BR
    note right
      R2: ACTIVE bookings of this room only;
      half-open intervals, touching is allowed (A2)
    end note

    alt overlapping not empty (R2)
      BS --> Student : rejected(ALREADY_BOOKED)
    else slot free
      BS -> BS : create Booking(studentId, roomId, start, duration, ACTIVE) with its Confirmation
      BS -> BR : save(booking)
      activate BR
      BR --> BS : saved(bookingId)
      deactivate BR
      BS --> Student : confirmation(code, bookingId, roomId, start, end)
      note right : R4
    end
  end
end

note over BS, BR
  A6: the blocked check, the overlap query and save run as one
  atomic unit per room, so two concurrent requests cannot both pass R2.
end note

deactivate BS
@enduml
```
